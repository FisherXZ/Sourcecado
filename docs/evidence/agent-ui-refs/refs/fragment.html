Claude.ai: common patterns

  • Most controls carry an icon. Steps and menu rows have a 16px icon or logo tile. Claude.ai uses icon-only for repeat actions (star, thumbs, close) and icon + word for the rest (Share, Copy, Retry).
  • The thread is quiet. A step is one bordered row: logo, verb + object in past tense, a result count, a chevron. The result opens under the row. Argument summaries are chips inside the row, not a second line.
  • Composer first. Home shows one greeting, one large composer and four icon prompt chips. While a run is active the same send button becomes a stop square and the placeholder says "Queue another message".
  • Results leave the thread. An inline card with an icon and "Open ..." opens a side panel with a title, a two-option switch, copy and download icons, and a close button.
  • State words carry the status: "Thinking..." becomes "Thought for 31 seconds"; "Searching messages" becomes "Searched messages"; chips read "Idle", "Needs input", "Running".
  • Permission prompts show the tool, the plain purpose, the exact payload, then numbered choices with the keys listed. Once, always (scoped) and no are separate choices.
  • Light and dark use the same layout. Only surface and ink change. The accent stays on the same elements in both.

Do not copy: text-only buttons (the footer labels "Accept edits", "Opus 5" and "High", and "Open component" have no icon); the 11 to 12px gray disclaimer and "Last edited" lines; gray "Result" toggles and the gray group header "Used 4 integrations"; the gray footer key hints in the permission prompt; the serif display greeting; the one-line narration under "Building the launch deck". The Console transcript shows the right content (tokens, time) but small. Set ours at 13px or more in ink. Every image below is a product marketing or docs render, so sizes are estimates from the screenshot, not from CSS.

Clay: common patterns

All images are Clay marketing, changelog and blog renders of the real app UI, not raw screenshots. Sizes below are ratios read from the images. Map them to our 13-14px body.

  • Light canvas, white surfaces, 1px light borders, almost no shadow inside the app. Cards sit near 8-10px radius, buttons near 6px. This fits Warm Operator with no change.

  • The placeholder does the labelling in the composer: "What do you want to do with Clay?". It changes to "Ask questions and add enrichments" once a thread exists.
  • One filled primary button per surface (Accept, Save, Import and run, Edit). All other buttons are outlined with an icon.

Do not copy: mid-gray secondary text (field labels, subtitles, empty-state text, "Not found" cells) and 11-12px chips break our 13px and no-muted rules.   • Every control has an icon: nav rows, tabs, chips, and action buttons all carry a 16px line icon before the label. Icon-only buttons are the default for secondary actions.
